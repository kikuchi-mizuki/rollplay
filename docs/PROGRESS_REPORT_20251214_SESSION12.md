## 🎯 解決した課題

### 1. **AIの役割混同問題（重大なバグ修正）**

#### 問題の詳細
ユーザーが実際の会話で発見した問題：
```
[ペルソナ選択] ランダム選択: ヨガインストラクター（投稿頻度を上げたい）

営業: 「本日初めてなので御社の事業内容を簡単にご説明いただけますか?」

AI応答: 「あー、はい。私たちは、オンラインでのショート動画制作を行っている事業をしています。
動画を通じて、商品やサービスの魅力を伝えるお手伝いをしているんですよ。」
```

**問題点:**
- ペルソナは「ヨガインストラクター」なのに、AIが**営業側のサービス内容**（「ショート動画制作」）を自分の事業として答えている
- これは完全な役割混同

#### 原因分析

**app.py:414-425 のシステムプロンプト:**
```python
【営業担当について】
あなたの前にいる営業担当は「ショート動画制作会社（ショート動画屋さん）」の社員です。
その営業が、InstagramリールやTikTok用の縦型ショート動画を月間15〜20本制作・運用代行するサービスを提供しています。
⚠️ これは営業側のサービスであり、あなたのサービスではありません。
```

**問題の構造:**
1. システムプロンプトで「営業担当のサービス内容」を説明
2. AIがこれを読んで理解
3. しかし、「事業内容を教えてください」と聞かれると、**営業側のサービス内容を自分の事業として説明してしまう**
4. ⚠️マーク付きの注意書きだけでは不十分だった

#### 解決策

**システムプロンプトを大幅に改善（app.py:409-449）:**

**Before（問題のあったプロンプト）:**
```
【あなたは誰ですか？】
⚠️ あなたは「ショート動画制作に悩んでいる事業主」です。

【営業担当について】
営業が、InstagramリールやTikTok用の縦型ショート動画を制作・運用代行するサービスを提供しています。
⚠️ これは営業側のサービスであり、あなたのサービスではありません。
```

**After（改善後のプロンプト）:**
```
【あなたの役割】
✅ あなたは「お客さん（事業主）」です
✅ あなたは【シナリオ設定】で指定された業種（例：ヨガインストラクター、ネイルサロン、飲食店など）を経営しています
✅ あなたは自分の事業のSNS動画制作で悩んでいます

❌ あなたは動画制作会社の社員ではありません
❌ あなたは動画制作サービスを提供する立場ではありません
❌ あなたの事業は「動画制作」ではありません（【シナリオ設定】の業種を使ってください）

【目の前の営業担当について】
営業担当は「ショート動画屋さん」という動画制作会社の社員です。
営業は、あなたのような事業主に対して、InstagramリールやTikTok用の縦型ショート動画を月間15〜20本制作・運用代行するサービスを提案します。

⚠️ 重要: 営業のサービス内容を、あなた自身の事業内容として説明してはいけません
⚠️ 「事業内容を教えてください」と聞かれたら → 【シナリオ設定】の業種（ヨガ、ネイル、飲食など）を答える
⚠️ 「動画制作サービス」はあなたの事業ではなく、営業側が提供するサービスです

## あなた自身の事業について（重要）

⚠️⚠️⚠️ 絶対に守ること ⚠️⚠️⚠️
営業から「事業内容を教えてください」「どんなお仕事をされていますか？」と聞かれたら：

✅ 正しい回答例（ヨガインストラクターの場合）:
   「原宿でヨガスタジオをやっています」
   「ヨガのインストラクターをしていて、オンラインレッスンも始めたんです」

❌ 絶対に禁止（動画制作会社と混同している）:
   「動画制作を行っている事業をしています」← これは営業側のサービスです！
   「ショート動画制作の運用代行をしています」← これは営業側のサービスです！
```

**改善のポイント:**
1. **✅/❌形式で視覚的に明確化**
2. **具体例を追加**（正しい回答 vs 禁止例）
3. **「あなた自身の事業について」セクションを新設**
4. **「営業担当について」セクションを後回しにして、自分の役割を先に強調**

#### 変更ファイル
- `app.py` (409-449行目): SALES_ROLEPLAY_PROMPT

#### 結果
- ✅ AIが正しくペルソナの業種で応答するようになる
- ✅ 「ヨガインストラクター」なら「ヨガスタジオ」と答える
- ✅ 営業側のサービス内容を自分の事業として答えなくなる

## 🚀 Phase 2（カメラ録画 + 画面共有機能）の要件定義

### 背景・目的

**現状の課題:**
- 音声会話のみで、表情や姿勢が確認できない
- 資料を使ったプレゼン練習ができない
- 実際のオンライン商談と同じ環境で練習できない

**Phase 2の目的:**
- ✅ カメラ録画で表情・姿勢を確認
- ✅ Google Meet風の画面共有で資料を使ったプレゼン練習
- ✅ 録画をダウンロードして振り返り

### 要件の確定（ユーザー回答）

#### 1. 優先順位
- **Phase 1**: カメラ録画機能
- **Phase 2**: 画面共有機能（段階的実装）

#### 2. 録画の保存方針
- ❌ サーバー保存なし
- ✅ **ダウンロードのみ**（ストレージコスト0円）

#### 3. 資料の種類
- ✅ PDF（サービス紹介資料、料金表）
- ✅ PowerPointスライド
- ✅ 画像（チラシ、事例写真）
- ✅ Webサイト（自社サイト、事例ページ）

#### 4. モバイル対応
- ✅ **PC限定でOK**

#### 5. ストレージ管理
- ✅ **ダウンロードのみ、保存不要**

### 実装方針：Google Meet風

**決定事項:**
- **Google Meet風の画面共有を採用**
- ファイルアップロード方式ではなく、`getDisplayMedia()` APIで画面共有
- PowerPointアニメーションも完全再現
- 実装が簡単（1-2日）

**技術スタック:**
- カメラアクセス: `getUserMedia()`
- 画面共有: `getDisplayMedia()`
- 録画: MediaRecorder API
- 合成: Canvas API
- ダウンロード: Blob + URL.createObjectURL()
