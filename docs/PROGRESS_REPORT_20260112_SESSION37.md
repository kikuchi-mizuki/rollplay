### 3. **AI音声品質問題の調査**

#### **報告された問題**
ユーザーからの報告：
1. 文章をちゃんと発言できていない
2. ビジネス会話なのに、1回の話が長すぎる

#### **調査結果**

##### **問題1: 文章をちゃんと発言できていない**

**原因**: チャンク分割が接続助詞で切られている

コード位置: `blueprints/conversations.py:1004-1014`

```python
# 接続助詞で分割するロジック
connectives = ['ですが', 'ますが', 'けど', 'けれど', 'ので', 'から']
best_pos = pos + len(conn)  # 「ますが」の後で切る
chunk_text = text_buffer[:best_pos].strip()
```

**具体例**:
```
チャンク3: "現在、月に10本の動画を外注していますが"
チャンク4: "、品質やコスト面での課題を抱えています。"
```

**問題点**:
- チャンク4が読点「、」から始まっている
- TTSが「、品質やコスト面で...」を正しく読めない
- 結果として「何を言っているかわからない音声」になる

---

##### **問題2: 1回の話が長すぎる**

**実際のAI発言例**:
```
"私たちは、東京を拠点にした動画制作会社です。企業向けのプロモーション動画や教育コンテンツを制作しており、クライアントのニーズに合わせたカスタマイズが特徴です。現在、月に10本の動画を外注していますが、品質やコスト面での課題を抱えています。"
```

**問題点**:
- **4文**を一度に話している
- システムプロンプトには「1発話は1-2文まで（長くても3文）」と記載
- 実際には守られていない

**現在の設定**:
- `max_tokens=1500`（app.py:409）← 長すぎる
- システムプロンプトの制約が弱い

---

## 📋 **修正方針**

### **修正1: チャンク分割ロジックの改善**

**場所**: `blueprints/conversations.py:965-1014`

**変更内容**:
- 接続助詞での分割を**廃止**
- 句点（。）でのみ分割
- 読点（、）から始まるチャンクを防止

**Before**:
```python
connectives = ['ですが', 'ますが', 'けど', 'けれど', 'ので', 'から']
# 接続助詞の後で切る
```

**After**:
```python
# 句点（。）でのみ分割
if '。' in text_buffer:
    pos = text_buffer.rfind('。')
    chunk_text = text_buffer[:pos+1].strip()
```

## 🔍 **技術的な発見**

### **TTS音声生成の仕組み**

1. **バックエンド（Python）**:
   - OpenAI TTS-1-HD APIで高品質音声を生成
   - Base64エンコードしてフロントエンドに送信
   - チャンク単位でストリーミング配信

2. **フロントエンド（TypeScript）**:
   - Server-Sent Events (SSE)でチャンクを受信
   - Base64デコード → ArrayBuffer変換
   - Web Audio APIで再生

3. **問題の原因**:
   - チャンク分割ロジックが不適切
   - 接続助詞で切ることで、読点から始まるチャンクが生成される
   - TTSは読点から始まるテキストを正しく読めない

### **チャンク分割の課題**

**現在のロジック**:
```python
# 最初のチャンク: 15文字以上で接続助詞を探す
if len(text_buffer) >= 15:
    connectives = ['ですが', 'ますが', ...]

# 2チャンク目以降: 25文字以上で接続助詞を探す
if len(text_buffer) >= 25:
    connectives = ['ですが', 'ますが', ...]
```

**問題点**:
- 接続助詞で切ると、次のチャンクが不自然な位置から始まる
- 例: 「ますが」→次が「、〜」となる

**解決策**:
- 句点（。）でのみ分割
- 自然な文の区切りを保つ
