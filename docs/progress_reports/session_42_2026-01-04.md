### 2. 第1回修正: トラック直接使用方式 (コミット `fd7221d`)

**問題の仮説**:
- MediaStreamDestinationのトラックをクローンしているため、音声データが流れない可能性

**対応内容**:

#### アーキテクチャ変更
**旧** (セッション41):
```
GainNode → MediaStreamDestination → トラッククローン → 録画
```

**新** (第1回修正):
```
GainNode ─┬→ AudioContext.destination (スピーカー)
          └→ MediaStreamDestination (録画) → トラック直接使用
```

#### 実装詳細

1. **RoleplayApp.tsx**: GainNodeを録画用MediaStreamDestinationに直接接続
```typescript
// AI音声ミキサー用のGainNodeを作成（常時接続）
const mixerGain = audioContext.createGain();
mixerGain.gain.value = 1.0;
aiMixerGainNodeRef.current = mixerGain;

// GainNodeをスピーカーに接続
mixerGain.connect(audioContext.destination);

// 録画用のMediaStreamDestinationを作成してGainNodeに接続
const recordingDestination = audioContext.createMediaStreamDestination();
mixerGain.connect(recordingDestination); // 録画用にGainNodeを接続
audioDestinationRef.current = recordingDestination;
```

2. **useRecording.ts**: AI音声トラックを直接使用（クローン削除）
```typescript
// AI音声トラックを直接追加（クローン不要 - GainNodeからMediaStreamDestinationに直接流れる）
aiAudioTracks.forEach(track => {
  track.enabled = true; // 明示的に有効化
  console.log(`    AI音声トラック[直接]: enabled=${track.enabled}, muted=${track.muted}, readyState=${track.readyState}`);
});
audioTracks.push(...aiAudioTracks);
console.log(`  AI音声: ${aiAudioTracks.length}トラック追加（GainNode→MediaStreamDestination直接接続）`);
```

**結果**: ❌ **失敗** - AI音声は依然として録音されない

### 3. 根本原因の特定

**MediaRecorderの動作メカニズムを深掘り**:

1. **MediaRecorderのトラックキャプチャタイミング**:
   - MediaRecorderは`start()`時にトラックの**スナップショット**を取得
   - その時点でトラックに音声データが流れていない場合、**後から音声が流れても録音されない**

2. **MediaStreamDestinationの特性**:
   - 接続されているノードから音声が流れている**瞬間だけ**データをストリームに送出
   - 音声が流れていない時は無音

3. **問題の流れ**:
```
[録画開始時]
1. 録画開始 (この時点でGainNodeに音声が流れていない)
2. MediaStreamDestinationのトラックを録画に追加
3. MediaRecorderがトラックのスナップショットを取得 ← この時点で無音
4. 後からAI音声がGainNodeに流れる ← もう遅い！録音対象外
```

### 4. 第2回修正: Oscillator連続信号方式 (コミット `03a95ec`)

**解決策**: **OscillatorNodeで極小音量の連続信号を送信**

#### なぜOscillatorNodeが必要か

**AudioBufferSource (セッション41で使用)**:
- 使い捨て（一度`start()`したら再利用不可）
- 再生終了後に自動切断される
- → 一度だけの無音再生では不十分

**OscillatorNode (今回の解決策)**:
- `start()`後、明示的に`stop()`するまで**永続的に動作**
- MediaStreamDestinationが**常にアクティブな状態を維持**
- AI音声が再生されると、Oscillatorの信号に重なって録音される

#### 実装内容

```typescript
// 極めて低い音量の連続信号でMediaStreamDestinationを常時アクティブ化
// (OscillatorNodeは停止するまで永続的に動作する)
const oscillator = audioContext.createOscillator();
const silenceGain = audioContext.createGain();
silenceGain.gain.value = 0.00001; // ほぼ無音（完全な0だと効果がない）
oscillator.connect(silenceGain);
silenceGain.connect(mixerGain);
oscillator.start();
console.log('🔇 MediaStreamDestinationをアクティブ化（極小音量の連続信号）');
```

#### 最終アーキテクチャ

```
[初期化時]
Oscillator(極小音量0.00001) → silenceGain → mixerGain ─┬→ MediaStreamDestination(録画用・常時アクティブ)
                                                         └→ AudioContext.destination(スピーカー)
                                 ↓
                        停止するまで永続的に動作

[AI音声再生時]
AudioBufferSource → mixerGain(既に接続済み) → 自動的に録画＆スピーカーへ
```

## 🎯 技術的なポイント

### MediaRecorderのスナップショット問題

**問題**:
- MediaRecorderは`start()`時にトラックのスナップショットを取得
- その時点で音声が流れていないと、後から流れても録音されない

**解決**:
- MediaStreamDestinationに常に信号を流し続ける
- OscillatorNodeで極小音量(0.00001)の連続信号を送信

### AudioBufferSource vs OscillatorNode

| 特性 | AudioBufferSource | OscillatorNode |
|------|------------------|----------------|
| 再利用 | ❌ 使い捨て | ✅ 永続的 |
| 接続維持 | ❌ 再生終了時に切断 | ✅ stop()まで維持 |
| 用途 | 録音済み音声の再生 | 連続的な信号生成 |
| MediaStreamDestination活性化 | ❌ 不適切 | ✅ 最適 |

### Web Audio APIノードの接続ルール

1. **AudioNode間の接続は永続的**: `connect()`で接続したら、`disconnect()`するまで維持
2. **AudioBufferSourceは例外**: `start()`したら、再生終了時に自動切断
3. **OscillatorNodeは永続的**: `start()`から`stop()`まで動作し続ける
4. **GainNodeは永続的**: 一度接続したら、明示的に切断するまで維持

### 極小音量(0.00001)の理由

- **完全な0 (gain.value = 0)**: Web Audio APIが最適化して信号を送らない可能性
- **極小値 (gain.value = 0.00001)**:
  - 人間の耳には聞こえないレベル
  - Web Audio APIは信号として認識
  - MediaStreamDestinationが確実にアクティブ化
